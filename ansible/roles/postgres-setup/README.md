# Роль `postgres-setup`

Ставит PostgreSQL на сервер базы, создаёт пользователя и базу приложения и открывает к ней доступ только из подсетей серверов приложения. Запускается плейбуком `db.yml` на инстансе с тегом `Role=db`.

```
приложение (10.60.11.0/24, 10.60.12.0/24) ──5432, scram-sha-256──> PostgreSQL 17
```

## Что делает

1. Ставит `postgresql17-server` и `python3-psycopg2`
2. Инициализирует кластер `postgresql-setup --initdb` — один раз, пока нет `PG_VERSION`
3. Запускает службу и включает автозапуск
4. Читает из SSM Parameter Store имя базы, пользователя, пароль и подсети приложения
5. Включает `listen_addresses` и добавляет в `pg_hba.conf` строки для подсетей приложения
6. Перезапускает PostgreSQL сразу, если конфигурация изменилась
7. Создаёт пользователя и базу, владелец базы — пользователь приложения

## Входы

**Снаружи** — из инвентаря при ручном запуске или из `ExtraVariables` ассоциации State Manager:

| Имя | Пример | Описание |
|---|---|---|
| `ssm_param_prefix` | `/week4/dev` | префикс параметров в Parameter Store |
| `aws_region` | `eu-central-1` | регион Parameter Store |

**Из Parameter Store** — создаёт Terraform:

| Параметр | Тип | Описание |
|---|---|---|
| `<prefix>/db_name` | String | имя базы |
| `<prefix>/db_user` | String | пользователь приложения |
| `<prefix>/db_password` | SecureString | пароль, сгенерирован `random_password` |
| `<prefix>/app_subnet_cidrs` | StringList | подсети серверов приложения для `pg_hba.conf` |

**`defaults/main.yml`** — можно переопределять:

| Имя | По умолчанию | Описание |
|---|---|---|
| `postgres_listen_addresses` | `"*"` | адреса, на которых слушает PostgreSQL |
| `postgres_auth_method` | `scram-sha-256` | метод аутентификации в `pg_hba.conf` |

**`vars/main.yml`** — константы, менять не нужно:

| Имя | Значение | Почему константа |
|---|---|---|
| `postgres_version` | `17` | от версии зависят имена пакетов |
| `postgres_packages` | `postgresql17-server`, `python3-psycopg2` | следуют из версии и требований модулей |
| `postgres_data_dir` | `/var/lib/pgsql/data` | определяется сборкой пакета в Amazon Linux 2023 |

## Пример

```yaml
---
- name: Configure PostgreSQL server
  hosts: all
  become: true
  roles:
    - postgres-setup
```

Ручной запуск через инвентарь из Terraform — обязательно с `--limit`, потому что в плейбуке `hosts: all`:

```bash
ansible-playbook -i inventory.ini db.yml --limit db
```

## Требования

- Amazon Linux 2023: AWS CLI v2 и пакет `acl` предустановлены
- роль инстанса с `ssm:GetParameter` на префикс параметров
- коллекция `community.postgresql` на машине, где запущен `ansible-playbook`

## Что здесь неочевидно

**`python3-psycopg2` из пакетов, а не `psycopg2-binary` через pip.** Модули `community.postgresql` выполняются на сервере базы системным Python, и им нужен драйвер именно там. Пакет есть в репозитории AL2023; ставить pip-пакеты в системный Python — плохая практика.

**Владелец базы — пользователь приложения.** Начиная с PostgreSQL 15 создавать таблицы в схеме `public` может только владелец базы. Оставь владельцем `postgres` — и миграции Django упадут с `permission denied for schema public`.

**`listen_addresses = '*'` — не дыра.** Снаружи порт закрывает security group (5432 открыт только для группы серверов приложения), внутри VPC — `pg_hba.conf`, который пускает только из двух подсетей и только пользователя приложения к его базе.

**`flush_handlers` перед созданием пользователя.** Обработчики выполняются в конце плейбука; без принудительного сброса новые сетевые настройки применились бы уже после того, как роль «закончила».

**Пароль читается на сервере командой `aws`, а не lookup-плагином.** Lookup выполняется там, где запущен `ansible-playbook`, — при запуске через SSM это сам сервер без `boto3`. Команда одинаково работает в обоих режимах. Задачи с паролем помечены `no_log: true`, чтение — `check_mode: false`, иначе в `--check` дальше шли бы пустые значения.

**Идемпотентность.** Второй прогон подряд: `ok=10 changed=0`.

## Что роль не делает

- не настраивает TLS — соединение внутри VPC идёт с `sslmode=prefer`, без сертификата
- не делает резервные копии и не настраивает репликацию
- не удаляет строки `pg_hba.conf` для подсетей, которые убрали из Terraform — только добавляет недостающие
- не тюнит параметры PostgreSQL под нагрузку

В production вместо этой роли была бы Amazon RDS: бэкапы, Multi-AZ и обновления из коробки. Роль существует потому, что задание требует поставить PostgreSQL самостоятельно.
