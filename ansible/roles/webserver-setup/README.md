# Роль `webserver-setup`

Готовит сервер приложения к запуску Django: Python 3.12, системные библиотеки, пользователь приложения, каталог, виртуальное окружение и nginx. Запускается плейбуком `webservers.yml` на инстансах с тегом `Role=app`.

## Что делает

1. Ставит `python3.12`, `git`, `libpq`
2. Создаёт системного пользователя `django` без shell
3. Создаёт каталог `/opt/django-sample-app` с владельцем `django`
4. Создаёт виртуальное окружение на Python 3.12 — один раз
5. Ставит nginx, запускает и включает автозапуск

## Входы

**`defaults/main.yml`:**

| Имя | По умолчанию | Описание |
|---|---|---|
| `app_user` | `django` | системный пользователь приложения |
| `app_dir` | `/opt/django-sample-app` | корневой каталог приложения |
| `app_venv` | `{{ app_dir }}/venv` | виртуальное окружение |

Те же три переменные с теми же значениями объявлены в роли `deploy`. Небольшое дублирование — цена того, что роли не зависят друг от друга.

**`vars/main.yml`:**

| Имя | Значение | Почему константа |
|---|---|---|
| `webserver_python` | `python3.12` | Django 6.1 требует Python ≥ 3.12 |
| `webserver_packages` | `python3.12`, `git`, `libpq` | следуют из требований приложения |

## Пример

```yaml
---
- name: Prepare application servers
  hosts: all
  become: true
  roles:
    - webserver-setup
```

```bash
ansible-playbook -i inventory.ini webservers.yml --limit webservers
```

## Требования

Только модули `ansible.builtin`. Amazon Linux 2023.

## Почему эта роль отдельно от `deploy`

Разделение по частоте изменений. Эта роль описывает **состояние машины** — оно меняется раз за жизнь сервера. `deploy` описывает **версию приложения** — она меняется каждый релиз. Смешать их — значит гонять `dnf` при каждом деплое и рисковать тем, что смена версии Python поедет вместе с правкой шаблона. Через SSM это две разные ассоциации: правка роли `deploy` не перезапускает эту роль.

## Что здесь неочевидно

**Python 3.12, а не системный `python3`.** Системный Python в Amazon Linux 2023 — 3.9. На нём работает Ansible, но не приложение: Django 6.1 требует ≥ 3.12 (проверено по метаданным пакета на PyPI). В `python3.12` из репозитория уже есть `venv` и `ensurepip`, отдельный `python3.12-pip` не нужен.

**Нет `gcc`, `*-devel` и `libcurl-devel`.** Они нужны только для сборки пакетов из исходников. Для всех зависимостей приложения с C-расширениями — `pycurl`, `cryptography`, `cffi`, `argon2-cffi-bindings`, `pydantic-core` — на PyPI есть готовые wheel под Python 3.12 и `manylinux x86_64`. Нужна только `libpq` без `-devel`: `psycopg 3` без суффикса `[binary]` загружает `libpq.so` во время работы.

**Код и окружение — соседние каталоги.** `venv` лежит в `/opt/django-sample-app/venv`, а код роль `deploy` клонирует в `/opt/django-sample-app/src`. Если положить окружение внутрь каталога кода, `git clone` упадёт: клонировать в непустой каталог нельзя.

**Окружение создаётся от пользователя `django`.** Иначе оно принадлежало бы root, и `deploy` не смог бы ставить в него пакеты от имени приложения.

**Пользователь без shell.** Если приложение взломают, у атакующего не будет интерактивного входа. Ansible при этом переключается на пользователя через `sudo`, а не через вход в shell, — это работает.

**nginx ставится здесь, а конфиг прокси кладёт `deploy`.** По схеме задания `nginx.conf` лежит в `deploy/files/`, а роль, которая читает файлы другой роли, — скрытая связь. Штатный `nginx.conf` в AL2023 не трогается: `include conf.d/*.conf` стоит в нём раньше встроенного `server`, а у нашего конфига `default_server`.

**Обработчиков нет.** Роль не меняет конфигурацию служб, звать перезапуск некому.

**SELinux** в AL2023 в режиме `Permissive`, поэтому проксирование nginx на локальный порт работает без `setsebool httpd_can_network_connect on`. На RHEL в режиме `Enforcing` это понадобилось бы.

**Идемпотентность.** Второй прогон подряд: `ok=7 changed=0`.

## Что роль не делает

- не выкатывает код и не ставит зависимости приложения
- не настраивает nginx как прокси и не запускает Django — всё это роль `deploy`
- не настраивает TLS в nginx — HTTPS в этой архитектуре должен заканчиваться на балансировщике
